# 二叉树：静态数组法 vs 动态指针法（建树原理 + 如何找根）

> 整理时间：2026-09-04 21:31:34
> 重点：① 两种建树方式的内存模型差异；② 两种情况下分别是怎么找到根结点的

## 0. 先给结论

- 静态数组法（参考代码）：结点编号 = 数组下标，left/right 存孩子编号；遍历时用 arr[编号] 当下标表寻址。找根方式：硬编码约定根就是编号 1，不主动找（代码里直接 preorder(node, 1)）。
- 动态指针法（你的代码）：TreeNode.left/right 存真实对象或 None，靠递归自底向上构建。找根方式：扫描父亲数组，谁的父亲是 -1 谁就是根（getRoot + fathers）。

下面分别展开为什么。

## 1. 静态数组法：编号即指针，数组即内存

### 1.1 建树模型

```python
node = [None] * (N + 1)          # 0 号空着当空结点哨兵，结点占 1..N
for i in range(1, N + 1):
    c, left, right = input().split()
    node[i] = TreeNode(c)
    node[i].left  = int(left)    # 存左孩子编号（整数！不是 TreeNode）
    node[i].right = int(right)   # 存右孩子编号
```

要点：结点的 left/right 字段是整数编号，不是指针。要走到孩子，靠数组下标：

```python
def preorder(arr, i):
    if i == 0:                   # 0 = 空（对应指针法的 None）
        return
    print(arr[i].val, end='')
    preorder(arr, arr[i].left)   # arr[i].left 是编号 → 去 arr[编号] 找左孩子
    preorder(arr, arr[i].right)
```

这里 arr 就是指针表：i 是手里的地址，arr[i] 是按地址取结点。这就是用数组模拟树的全部秘密——编号当指针、数组当下标表。

### 1.2 静态法怎么找根：它根本不找，直接约定是 1

```python
preorder(node, 1)   # 根硬编码为编号 1
```

为什么是 1？两个原因叠加：
1. 数组是 1-based：node[0] 特意留空，真实结点住在 node[1..N]，且结点编号 = 数组下标（第 i 行输入就放进 node[i]）。
2. 这份参考代码（以及它对应的题目）约定根结点编号为 1，于是遍历直接从下标 1 开始。

注意这是信任约定，不是计算出来的：代码里没有任何找根逻辑。隐含前提是题目保证根是 1。如果某题根不是 1，这段静态代码就会出错——这是它相比动态法不够通用的地方。

### 1.3 静态法的根为什么一定是 1（从输入角度）

输入每行是 名字 左孩子编号 右孩子编号，孩子编号引用的是 1..N 里的下标。根定义为没有任何结点以它为孩子。但参考代码没去验证这一点，而是直接假定第 1 行就是根、编号为 1。所以 preorder(node, 1) 成立的前提是：该题中根的编号恰为 1（这是题目/参考代码的人为约定）。

## 2. 动态指针法：真实对象 + 父亲数组找根

### 2.1 建树模型

```python
class TreeNode:
    def __init__(self, x='a', left=None, right=None):
        self.val = x
        self.left = left        # 这里存真正的 TreeNode 对象或 None
        self.right = right

N = int(input())
fathers = [-1] * N             # 每个结点的父编号，初始 -1
names   = ['0'] * N
sons    = [(-1, -1)] * N       # 每个结点的（左,右）孩子编号，初始 -1
for i in range(N):
    name, left, right = input().split()
    left, right = int(left), int(right)
    sons[i] = (left - 1, right - 1)     # 1-based → 0-based，0 变 -1（无孩子）
    if left  != 0: fathers[left  - 1] = i
    if right != 0: fathers[right - 1] = i
    names[i] = name
```

区别：这次 left/right 是真实 TreeNode。孩子编号用 1-based 输入，统一 -1 转成 0-based 的空哨兵（对应静态法的 0）。

构建真实树（自底向上 / 后序构造）：

```python
def preorder_build(rt, sons, names):
    if rt == -1:
        return None
    left  = preorder_build(sons[rt][0], sons, names)   # 先建左子树
    right = preorder_build(sons[rt][1], sons, names)   # 再建右子树
    return TreeNode(names[rt], left, right)           # 最后造父结点，接上左右
```

函数名 preorder_build 只是从根入口，真正的内存构造顺序是后序：先把左右子树递归建好（拿到它们的根对象），再 return TreeNode(...) 把当前结点造出来、把左右孩子接上去。

### 2.2 动态法怎么找根：扫描父亲数组

```python
def getRoot(fathers, sons):
    root = 0
    while root < N:
        if fathers[root] == -1:   # 没有父结点 → 就是根
            break
        else:
            root += 1
    return root
```

原理：根的定义是本身不被任何结点当作孩子。代码在 fathers 里找第一个值为 -1 的下标——它父亲不存在，所以它就是根。
- 这不依赖根是 1 的约定，输入里根在任意位置都能正确找到，比静态法通用。
- 配套：建树时 if left != 0: fathers[left-1] = i 把谁是谁的父记下来，找根才有据可依。

### 2.3 用根递归建树

```python
root = getRoot(fathers, sons)
self.root = preorder_build(root, sons, names)
```

拿到根编号后，从根出发递归把整棵指针树拼出来，self.root 指向真正的根 TreeNode。

## 3. 两种找根对比（本 md 的核心）

| | 静态数组法（参考代码） | 动态指针法（你的代码） |
|---|---|---|
| 根的存放 | 不存，直接用编号 1 | self.root 指向真实根结点 |
| 找根依据 | 无——硬编码约定 root=1 | 扫描 fathers，father==-1 即根 |
| 找根代码 | 不存在（preorder(node, 1)） | getRoot() 循环找第一个 -1 |
| 是否依赖输入约定 | 是（必须根=1，否则错） | 否（根在任意位置都行） |
| 通用性 | 弱 | 强 |
| 代价 | 简单、O(1) 起步 | 需维护 fathers，多一遍 O(N) 扫描 |

一句话归纳：
- 静态法不找根，它站在题目保证根是 1 的约定上，直接用编号当下标从 node[1] 遍历——简洁但挑输入。
- 动态法显式找根，用父亲数组反查出 fathers==-1 的结点当根，再递归建真实指针树——不挑输入、更稳。

## 4. 易错点

1. 静态法最易踩的坑：以为 preorder(..., 1) 的 1 是算出来的。它不是，是约定。换题根若不是 1，必须先 getRoot 或从输入里识别根，否则整个遍历从错的位置开始。
2. 动态法转 0-based 时 -1 哨兵必须做：输入给的 0（无孩子）减 1 得 -1，否则 0 号结点会被当成真实结点（对应静态法里 i==0 判空）。
3. fathers 要初始化全 -1，且只在 left/right != 0 时才写父关系；漏条件会导致找不到根或父子错位。
4. preorder_build 名字有误导性：构造顺序是后序（先孩子后父），不是先序；名字只表示入口从根开始。
5. 遍历部分两者完全一致：只看根 / 左 / 右 的相对位置（前/中/后序），载体是指针还是编号不影响遍历逻辑。

## 5. 一句话总览

静态法 = 编号当指针 + 数组当下标表，根靠约定=1 直接用；动态法 = 真实对象递归构建，根靠父亲数组里 -1 显式找出。前者快但挑输入，后者稳且通用。
