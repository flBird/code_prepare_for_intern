# 链表基本操作与 ACM 模式

> 整理时间：2026-09-04 17:01:16
> 对应代码：带头结点单链表（get / delete / insert / show / initialize）

## 1. 代码功能概述

这是一个用 Python 实现的「带头结点单链表」，支持：
- `initialize(l)`：用列表初始化链表
- `get(a)`：取第 a 个结点的值（1-based，即第 1 个是首元结点）
- `delete(a)`：删除第 a 个结点
- `insert(a, e)`：在第 a 个位置**之前**插入元素 e
- `show()`：打印整条链表
- `operate_link(s)`：把一行命令字符串解析成对应操作

外层输入逻辑（ACM 模式）：
```python
L = link()
L.initialize(list(map(int, input().split()))[1:])
N = int(input())
for _ in range(N):
    L.operate_link(input())
```

## 2. ACM 模式（重点）

ACM 模式 = 程序从**标准输入 stdin** 连续读入、按题目约定格式处理、把结果打印到**标准输出 stdout**；
不依赖任何框架/主函数模板，读多少、何时结束都由输入本身决定。

本段代码的输入约定：
```
第 1 行：元素个数 k，以及 k 个元素（空格分隔）
第 2 行：操作次数 N
接下来 N 行：每行一条命令，如 "insert 1 10" / "delete 2" / "show" / "get 3"
```

对应要点：
- 用 `input()` 逐行读，循环固定 N 次，这是 ACM 多组/多次操作的标准写法。
- `list(map(int, input().split()))[1:]`：`split()` 按空白切分成字符串列表 → `map(int, …)` 转成 int 列表 → `[1:]` 跳过首位的"元素个数"。
- 与「核心代码模式」（LeetCode 那种只写函数、输入由平台封装）不同，ACM 模式要自己读输入、自己控制结束。
  若遇到"组数未知"的输入，通常用 `try / except EOFError` 包裹 `input()`；本例用 N 显式控制，是已知用例数的简化版。

## 3. join 模式要求列表元素是 str（重点）

`show()` 把链表转成列表后用 `join` 拼成一行字符串输出：
```python
l = []
while cur:
    l.append(cur.val)        # val 是 int
    cur = cur.next
print(' '.join(map(str, l))) # 必须 map(str, l)
```

为什么必须 `map(str, l)`？
- `'<sep>'.join(iterable)` 要求 iterable 里的**每个元素都是字符串**；若元素是 int，Python 会直接抛
  `TypeError: sequence item 0: expected str instance, int found`。
- `map(str, l)` 把每个 int 转成 str，join 才能正常工作。
- 记忆一对互逆操作：读入用 `split → map(int)`，输出用 `map(str) → join`。

## 4. insert 的判定：检查"走了多少步"，不是 cur.next（重点）

错误思路：用 `cur.next is None` 判断插入失败。
正确思路：用 `i < a-1` 判断"是否真的走够了 a-1 步"，即是否到达了目标前驱结点。

正确写法：
```python
def insert(self, a, e):
    cur = self.dummyhead
    i = 0
    while cur.next and i < a - 1:   # 走 a-1 步，到达"第 a 个位置的前驱"
        cur = cur.next
        i += 1
    if i < a - 1:                    # 关键：用"步数"判定，而非 cur.next
        print('insert fail')
        return
    tmp = self.Node(e, cur.next)
    cur.next = tmp
    print('insert OK')
```

为什么不能用 `cur.next is None` 判定？
- 插入位置 a 是 1-based，需要走到第 a-1 个结点（前驱）。循环 `while cur.next and i < a-1` 会因两种原因停下：
  ① 走够了（i == a-1，成功）；② `cur.next` 为空（链表到头，没走够）。
- 若用 `if cur.next is None` 判失败，会**误杀合法的"尾部追加"**：例如链表为 1→2，要在第 3 个位置插入（a=3，a-1=2）。
  走到 cur = 结点2（i=2）时循环正常结束，但结点2 就是尾结点，`cur.next` 为 None——
  这其实是一次完全合法的"在末尾追加"，却会被 `cur.next is None` 错判成失败。
- 而 `if i < a-1` 只关心"步数够不够"：步数够（i == a-1），无论 `cur.next` 是否为空都允许插入
  （cur.next 为 None 时就是把新结点接在尾巴上）；步数不够（i < a-1，说明链表太短、根本没有那个前驱），才判失败。这正是正确语义。

对比 delete：delete 要删的是 `cur.next` 这个结点，所以 delete 失败的条件确实是 `cur.next is None`
（没有可删的结点），和 insert 不同——insert 是接在 cur 后面，cur 本身存在即可。这是两者判定条件看似相似、实则不同的关键。

## 5. 其它隐藏 bug（附赠）

1. `initialize` 会逆序：
```python
def initialize(self, l):
    for k in l:
        tmp = self.Node(k, self.dummyhead.next)
        self.dummyhead.next = tmp   # 每次都插到表头 → 链表被反转
```
例如输入 1 2 3，得到的是 3→2→1。若要保序，应维护尾指针做尾插：
```python
def initialize(self, l):
    tail = self.dummyhead
    for k in l:
        tail.next = self.Node(k)
        tail = tail.next
```

2. `get` 的 `if cur is None` 是死代码：
```python
while cur.next and i < a:
    cur = cur.next
    i += 1
if cur is None:        # cur 永远指向某个真实结点，不可能为 None
    print('get fail')
```
cur 永远不为 None，正确判失败应是 `if i < a:`（没走够，说明 a 超出长度）；否则 a 越界时会错误地打印最后一个结点的值。

3. `self.len` 初始化了却全程未维护；若要 O(1) 取长度，需在 insert/delete 时同步更新。

## 6. 复杂度

- `get / delete / insert` 均需 O(a) 走到目标位置，最坏 O(n)。
- `show` 遍历一次 O(n)。
- 整体随操作数线性增长；用数组/vector 实现随机访问可把单步降到 O(1)，但本题考察的是链表指针操作。
